# plan.md — JSONLens: a desktop JSON viewer, formatter and CSV exporter (Electron)

> **For Claude Code:** This is the build spec for a new Electron desktop app. Work through the **Phases** (section 12) in order. Finish each phase's acceptance criteria and get its tests passing before you start the next one. If something here is ambiguous, pick the simplest option that still meets the **performance requirements** (section 3), and leave a short `// DECISION:` comment explaining the choice. Do not quietly remove a feature. `JSONLens` is a working name, kept in one constant (`APP_NAME`) so it's easy to change.

---

## 1. Goal

A fast, offline desktop app (macOS, Windows, Linux) modelled on **jsonviewer.stack.hu**, with CSV export modelled on **convertcsv.com/json-to-csv.htm**. It does four things:

1. **Smart format.** You paste messy, escaped, double-stringified or slightly broken JSON and get valid, pretty-printed JSON back. Escape sequences like `\n`, `\t`, `\r`, `\"` are cleaned up correctly.
2. **Tree viewer.** A nested tree you can expand and collapse, with colour-coded type badges and a property panel (as in stack.hu).
3. **CSV export.** Nested data is flattened sensibly, with options for how arrays are handled, a preview, and output streamed to disk.
4. **Large payloads.** 100k+ lines must feel smooth, and 1M+ lines must work. All heavy work happens off the UI thread, behind a loader you can cancel.

## 3. Performance requirements (non-negotiable)

**Test fixtures**, generated by `scripts/gen-fixtures.ts`:

- `small.json`: about 1k lines
- `medium.json`: **about 100k lines, roughly 4 MB** (the main target)
- `large.json`: about 1M lines, roughly 40 MB
- `huge.json`: about 200 MB (stretch goal: must not crash, slower is acceptable)
- Variations: deep nesting (depth 200+), very wide objects (10k keys), long strings (1 MB values), large arrays of objects (as in API exports), double-stringified versions of each

**Budgets** for `medium.json` on a typical laptop:

| Operation | Budget |
|---|---|
| Paste, then sanitise, parse, format and index | < 1.5 s, with the loader showing if it takes > 150 ms |
| UI main thread | **No task over 100 ms, ever.** Parsing, repair, formatting, indexing, search and CSV generation all run in a worker |
| Tree scrolling | 60 fps, with only about 50–100 DOM rows mounted at any time |
| Expanding or collapsing one node | < 50 ms |
| Expand all / collapse all | < 300 ms |
| Search over all keys and values | < 500 ms |
| CSV export (10k-row array of objects) | < 3 s, streamed to disk |

**Architectural rules that follow from these budgets:**

1. **Never** call `JSON.parse`, `JSON.stringify`, the repair code or tree-walking on the renderer's main thread.
2. **Never** make one DOM node per JSON node. The tree is a virtualised flat list.
3. Pass large data between threads as **transferable `ArrayBuffer`s or typed arrays** wherever possible, not as deep object graphs.
4. The parsed JSON object lives **only inside the worker**. The UI gets a compact, flat index (section 6).
5. Every long-running job reports progress and can be **cancelled** (terminate the worker and start a fresh one).
6. Raise the V8 heap limit in main with `app.commandLine.appendSwitch('js-flags', '--max-old-space-size=8192')`, so the huge fixtures don't run out of memory.

## 4. Architecture

```
┌──────────────────────── Main process (Node) ────────────────────────┐
│ window mgmt · native menus · file open/save dialogs                 │
│ fs read (→ ArrayBuffer) · streaming CSV/JSON writer (createWriteStream)│
└───────────────▲──────────────────────────────────▲──────────────────┘
                │ ipc (typed, via preload)         │ MessagePort (CSV/JSON chunks)
┌───────────────┴──────── Renderer (React UI) ─────┼──────────────────┐
│ Editor (CodeMirror) · TreeView (virtualised) · PropertyPanel        │
│ Toolbar · LoaderOverlay · CsvExportDialog · StatusBar               │
│ holds: flat tree index (typed arrays), expanded bitset, selection   │
└───────────────▲──────────────────────────────────┼──────────────────┘
                │ postMessage (RPC + progress)     │
┌───────────────┴──────── Web Worker: json.worker.ts ┴────────────────┐
│ sanitize → parse → (lossless if needed) → format → build index      │
│ holds: parsed JSON root (source of truth)                           │
│ serves: getValue(id), search, getPath, formatText, CSV generate     │
└─────────────────────────────────────────────────────────────────────┘
```

- **The worker** is a single long-lived module worker (`new Worker(new URL('./json.worker.ts', import.meta.url), { type: 'module' })`) wrapped in a small promise-based RPC client (`workerClient.ts`). Each request has an `id`, and progress events carry that `id`.
- **Cancelling** a job terminates the worker, starts a new one, and resets the app to its previous good state.
- **File loading.**
  - Drag and drop: use the `File` object in the renderer, call `file.arrayBuffer()` and transfer it to the worker. Nothing goes through IPC.
  - Open dialog: main reads the file into a `Buffer`, sends it as an `ArrayBuffer`, the renderer transfers it to the worker, and the worker decodes it with `TextDecoder` (stripping any BOM).
- **Streaming exports.** The renderer creates a `MessageChannel`. One port goes to the worker and the other goes to main (`ipcRenderer.postMessage('export:port', null, [port])`). The worker sends string chunks of about 1 MB straight to main, which writes them to the chosen path with a write stream and reports bytes written. The UI thread never handles the CSV text.

## 5. Feature 1: smart format and sanitiser

File: `src/worker/sanitize.ts`. This is a **pure function** with thorough unit tests.

```ts
interface SanitizeResult {
  ok: boolean;
  value?: unknown;              // parsed root (stays in worker)
  fixes: string[];              // human-readable list, e.g. "Unwrapped double-stringified JSON (2 levels)"
  error?: { message: string; line: number; column: number; snippet: string };
  usedLossless: boolean;
}
```

### 5.1 The pipeline

The steps below run in order. As soon as one produces a valid parse, the pipeline stops, apart from the unwrap loop in step 2. Every transformation that is applied is recorded in `fixes`.

0. **Normalise.** Strip the BOM, trim, and convert `\r\n` to `\n`. Remove zero-width or non-breaking space characters that sit **outside** strings.
1. **Direct parse.** Try `JSON.parse(text)`.
2. **Unwrap double-stringified JSON.** If the parse succeeds but the result is a **string** whose trimmed contents start with `{` or `[` (or is a quoted JSON string), parse it again. Repeat up to 5 times. This turns `"{\"a\":1,\"b\":\"x\"}"` into `{a:1,b:"x"}`.
3. **Escaped string without its outer quotes.** If the text contains `\"` at structural positions (for example it starts with `{\"`), try `JSON.parse('"' + text + '"')` and then go back to step 2. This handles text copied from inside a log line or code literal, such as `{\"a\":1}`.
4. **Literal escapes between tokens.** Use a **character-level state machine** (states: `OUTSIDE_STRING`, `IN_STRING`, `ESCAPE`) to turn the literal two-character sequences `\n`, `\t`, `\r`, `\f`, `\b` into plain whitespace **only when they appear outside a string**. Inside strings they are valid JSON escapes and **must be kept**, because they are part of the value. This handles `{\n\t"name": "a\nb"}` (literal backslashes) and gives `{"name": "a\nb"}`.
   - In the same pass, if **all** structural quotes are written as `\"`, turn them into `"` (but leave `\\"` inside values alone).
   - Remove an unescaped trailing `\` left over from line continuations.
5. **Over-escaped content.** If the text contains `\\n` or `\\"` with a regular pattern (everything escaped exactly one extra level), remove one level of escaping and try again.
6. **Strip wrappers.** Handle common copy-paste debris: a leading `var x =` or `const x =`, a trailing `;`, JSONP `callback(...)`, surrounding backticks or code fences (```` ```json ````), and log prefixes before the first `{` or `[` (for example `2026-11-06T10:00:00Z INFO payload=`). Only strip when what's left parses.
7. **Relaxed JSON repair.** Run `jsonrepair(text)` for trailing commas, single quotes, unquoted keys, comments, `True/False/None`, `NaN`, missing commas, and truncated endings. Record a fix such as "Repaired non-standard JSON".
8. **Also accept NDJSON.** If the text has several lines and each one parses on its own, wrap them in an array and record a fix.
9. **Give up clearly.** If nothing works, return the error from the **original** text's parse, with line, column, a snippet showing about 40 characters on each side, and a caret marking the error. The editor highlights and scrolls to that position.

### 5.2 Extra options (in the settings popover)

- **Expand nested stringified JSON** (off by default). Walk the parsed tree, and for any string value that starts with `{` or `[` and parses, replace it with the parsed value. Record the number of fields expanded.
- **Big-number safety** (on by default). Before parsing, run a cheap scan for any number literal with 16 or more significant digits, or a very large exponent. If one is found, parse with `lossless-json` (big integers become `LosslessNumber`), then show them in the tree with a "big" marker and write them back out unchanged when formatting or exporting.
- **Indent** (2, 4 or tab), **sort keys** (alphabetical, recursive), and **minify**.

### 5.3 Formatting output

The worker runs `JSON.stringify(value, null, indent)`, or a custom streaming serialiser when the result is likely to be above about 50 MB, so there isn't one giant intermediate string. The editor then receives the text.

**Editor size threshold:** if the formatted text is above **25 MB** (configurable), don't load it into the editor automatically. Show a banner: "Large document: showing tree view. [Load in editor anyway] [Save formatted JSON…]". Saving streams through the export port.

### 5.4 Required unit tests (`sanitize.test.ts`)

| Input (as raw typed characters) | Expected |
|---|---|
| `{"a":1}` | parses directly, no fixes |
| `"{\"a\":1}"` | `{a:1}`, fix "unwrapped 1 level" |
| `"\"{\\\"a\\\":1}\""` | `{a:1}`, unwrapped 2 levels |
| `{\"a\":\"x\"}` | `{a:"x"}` |
| `{\n\t"a": "line1\nline2"}` (literal `\n` and `\t`) | `{a:"line1\nline2"}`, with the newline inside the value kept |
| `{"a":1,}` | repaired |
| `{'a': True, b: None}` | `{a:true,b:null}` |
| `callback({"a":1});` | `{a:1}` |
| ```` ```json\n{"a":1}\n``` ```` | `{a:1}` |
| `INFO 12:00 payload={"a":1}` | `{a:1}` |
| `{"id": 12345678901234567890}` | id kept exactly (lossless) |
| `{"a":1}\n{"a":2}` | `[{a:1},{a:2}]` (NDJSON) |
| `{"a": ` (truncated) | repaired, or a clear error with the line and column |
| `{"msg":"tab\there"}` | value keeps its tab, nothing outside the string changes |

## 6. The flat tree index (the core of large-payload performance)

The worker builds this in a **single pre-order walk**, using an explicit stack rather than recursion so that depth can't cause a stack overflow. It posts progress about every 50k nodes.

```ts
// All arrays have length N = node count; node 0 is the root.
interface TreeIndex {
  n: number;
  type: Uint8Array;        // 0 obj, 1 arr, 2 str, 3 num, 4 bool, 5 null, 6 bignum
  depth: Uint16Array;
  parent: Int32Array;      // -1 for root
  subtreeEnd: Int32Array;  // index one past the last descendant (for skipping collapsed subtrees)
  childCount: Int32Array;
  // label data (strings) — sent once, structured-cloned:
  keys: string[];          // property name, or "" for array items (UI shows index)
  arrayIndex: Int32Array;  // index within parent array, else -1
  preview: string[];       // value preview truncated to 200 chars ("{12}", "[3400]" for containers)
}
```

- Typed arrays are **transferred**, so there's no copy.
- **Visible rows** are computed in the renderer, in O(number of visible rows):

```ts
function computeVisible(idx: TreeIndex, expanded: Uint8Array): Int32Array {
  const out = new Int32Array(idx.n); let k = 0, i = 0;
  while (i < idx.n) {
    out[k++] = i;
    const container = idx.type[i] <= 1;
    i = container && !expanded[i] ? idx.subtreeEnd[i] : i + 1;
  }
  return out.subarray(0, k);
}
```

- The **expanded state** is a `Uint8Array(n)` bitset. "Expand all" sets every entry, "collapse all" clears every entry, and "expand to level N" sets entries where `depth < N`. Each is a single linear pass.
- **Default view:** the root and its first level are expanded (stack.hu does the same).
- **Path of a node:** walk `parent` up to the root and build a JSONPath such as `$.data.items[42].name` (use bracket notation for keys that aren't valid identifiers).
- **Full value** of a node (when the preview was truncated, or for copying a subtree): `worker.getValue(id)` returns the exact value, or formatted text for a subtree. The worker finds the node by following the stored `parent` and key path from the root.

## 8. Feature 3: CSV export (modelled on convertcsv.com)

File: `src/worker/csv.ts`. A pure, streaming generator with thorough tests.

### 8.1 Dialog (`CsvExportDialog`)

1. **Source.** Choose whether to export from the root or from the selected node. Then choose the **array to convert**. The worker auto-detects candidates by scanning for arrays of objects and lists them by path and length (for example `$.data.orders [12,430]`). The largest is selected by default.
   - If the source is a single object, it becomes one row.
   - If it's an array of primitives, it becomes a one-column CSV with a `value` header.
2. **Flattening options:**
   - **Path separator**: `.` (default), `/` or `_`. For example, `{"user":{"address":{"city":"X"}}}` becomes the column `user.address.city`.
   - **Max depth** (default unlimited). Anything deeper is written as a JSON string.
   - **Array handling.** There's a global default, plus an optional per-path override for detected arrays:
     - `join`: arrays of primitives are joined with a configurable separator (default `; `), for example `tags` becomes `a; b; c`. This is the default for primitive arrays.
     - `index`: one column per index, for example `tags.0`, `tags.1`, `items.0.sku`, with the number of columns capped (default 50).
     - `explode`: **one row per array element**, with the parent fields repeated on each row. Only **one** array path can be exploded at a time, so the row count can't multiply across several arrays. The dialog shows the estimated row count before export.
     - `json`: the whole array is written as a JSON string in one cell. This is the default for arrays of objects that aren't exploded.
3. **Output options:**
   - Delimiter: `,` (default), `;`, tab or `|`.
   - Quote: only when needed (default) or always.
   - Header row on or off.
   - **UTF-8 BOM** so Excel opens it correctly (off by default; the label says "Excel compatibility").
   - Line endings: LF or CRLF (CRLF by default on Windows).
   - `null` written as an empty cell (default) or as the text `null`.
   - Booleans written as `true/false` or `TRUE/FALSE`.
4. **Preview.** A virtualised table of the first 100 rows, which updates live (with debouncing) as options change. It shows the total number of rows and columns.
5. **Export.** Opens the native save dialog, then the CSV streams to disk with a progress bar and a Cancel button. When it finishes, a toast shows "Saved 12,430 rows × 37 columns" with a "Show in folder" button.

### 8.2 Algorithm (two passes, streaming)

- **Pass 1 (columns):** walk every row record and collect flattened keys **in the order they first appear** into an ordered set. This handles records with different shapes, because the result is the union of all columns. If there are more than 5,000 columns, warn and suggest switching array handling to `json` or `join`.
- **Pass 2 (rows):** flatten each record into a `Map<column, string>`, write the cells in column order, and **escape them according to RFC 4180**: quote a cell if it contains the delimiter, a quote, CR or LF, and double any quotes inside it.
- **CSV injection protection** (on by default, can be turned off): prefix a `'` to cells that start with `=`, `+`, `-` or `@` **when they aren't numbers**.
- Collect output into chunks of about 1 MB and post each to the export port. Post progress every 1,000 rows.
- Big numbers are written as their exact original text.

### 8.3 Required unit tests (`csv.test.ts`)

Cover: flat objects; nested objects (columns named with dots); records with different shapes (union of columns, with empty cells where a value is missing); each array mode (`join`, `index`, `explode`, `json`); exploding with the parent fields repeated; delimiter, quote and newline escaping; unicode and emoji; a BOM; injection protection; a root that's a single object; an array of primitives; an empty array; and a 100k-row run that finishes inside the budget.

## 9. Loader and feedback

- `LoaderOverlay` appears only if a job takes **more than 150 ms**, so short jobs don't flicker. It's a translucent overlay over the content area, and the toolbar is disabled while it's showing.
- It contains:
  - A smooth, CSS-only animated loader (for example an indeterminate ring or bar; no heavy GIFs).
  - The **current stage**: "Reading file…", "Cleaning up escapes…", "Parsing…", "Building tree (45%)…", "Formatting…", "Writing CSV (8,200 / 12,430 rows)…".
  - A **determinate progress bar** whenever the stage can report a percentage.
  - Elapsed time, and a **Cancel** button (Esc also cancels).
- Errors appear as a red banner in the Text tab, with the message, line and column, and a "Jump to error" button. The previous good tree is kept.
- Toasts confirm copies, saves and exports.

### Worker RPC contract (in `shared/types.ts`)

```ts
type Req =
  | { id: number; kind: 'load'; buffer: ArrayBuffer; opts: SanitizeOptions }   // bytes in
  | { id: number; kind: 'loadText'; text: string; opts: SanitizeOptions }       // paste
  | { id: number; kind: 'format'; indent: 2 | 4 | '\t'; sortKeys: boolean; minify: boolean }
  | { id: number; kind: 'getValue'; nodeId: number; asText: boolean }
  | { id: number; kind: 'search'; query: string; opts: SearchOptions }
  | { id: number; kind: 'csvCandidates'; fromNode: number }
  | { id: number; kind: 'csvPreview'; opts: CsvOptions; limit: number }
  | { id: number; kind: 'csvExport'; opts: CsvOptions; port: MessagePort }
  | { id: number; kind: 'saveJson'; indent: 2 | 4 | '\t'; port: MessagePort };

type Res =
  | { id: number; kind: 'progress'; stage: string; pct?: number }
  | { id: number; kind: 'loaded'; index: TreeIndex; fixes: string[]; stats: Stats; formatted?: string }
  | { id: number; kind: 'error'; error: SanitizeResult['error'] }
  | { id: number; kind: 'result'; data: unknown };
```
